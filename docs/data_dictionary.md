# Data Dictionary (SYNTHETIC DATA)

All data is generated by `cloudspend.data_generation.generate_billing` with a fixed seed (default 42).
It is not real billing data and is unaffiliated with any cloud provider.

## `cloud_billing_<profile>.csv` — grain: one row per resource per day
| Field | Type | Notes |
|---|---|---|
| record_id | string | Unique (`<profile>-rec-00000000`, e.g. `demo-rec-00000000`) |
| usage_date | date | |
| department / service_name / environment / region | string | Fixed per resource; allowed values in `generate_billing.py` |
| resource_id | string | `res-0000` |
| usage_units | decimal(2dp) | |
| unit_cost | decimal | Constant per service |
| total_cost | decimal(2dp) | `round(usage_units * unit_cost, 2)`; validated within $0.01 |
| is_injected_anomaly | bool | Ground truth, **evaluation only — never a model feature** |
| anomaly_type | string/null | `spike`, `drift`, `weekend_spend` |
| generated_at | timestamp | Fixed constant so output is reproducible |

## `budgets_<profile>.csv` — grain: month x department x service
| Field | Notes |
|---|---|
| budget_month | First day of month |
| department, service_name | |
| budget_amount | Monthly amount. Stored separately from daily rows so it can't be double-counted. |

## Profiles
| Profile | Start | Days | Resources | Spikes | Drifts (7 labelled days each) | Weekend |
|---|---|---|---|---|---|---|
| dev | 2025-01-01 | 180 | 24 | 6 | 2 | 3 |
| demo | 2024-07-01 | 548 | 72 | 30 | 8 | 10 |

## Assumptions
- Usage = base x resource size x environment scale x linear growth x weekly x yearly seasonality x log-normal noise.
- Anomalies are injected only after the first 60 days so baselines have clean history.
- Spike: one-day usage x3–6. Drift: 14-day ramp to x2.2 (last 7 days labelled). Weekend: non-production, one weekend day x3.
- Budget = actual monthly spend x U(0.85, 1.10) (synthetic planning noise), so some groups run over budget.
- Deviation from spec: `budget_amount` is not a column of the billing file (see above).
